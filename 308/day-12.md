  <h2>Two ways to cut \(D_6\)</h2>

  <p>Section 6.1 defines the left coset \(gH = \{gh : h \in H\}\) and the right coset \(Hg = \{hg : h \in H\}\),
    for a subgroup \(H\) of \(G\) and an element \(g\) of \(G\). This widget uses \(D_6\), the symmetries of a
    hexagon: twelve elements and plenty of subgroups to try.</p>

  <p>The menu picks a subgroup \(H\). The left column lists the left cosets, the right column the right cosets, and
    each chip is one coset. Before you touch the menu, predict:</p>
  <ul>
    <li>Will the two columns ever list the same sets?</li>
    <li>How many elements will be in each chip?</li>
  </ul>

  <div id="d12-cosets"></div>

  <p>The default is \(H = \langle s \rangle\), the two-element subgroup generated by one flip. Find \(rH\) and \(Hr\)
    in the two columns. Some chips match across the columns, such as \(r^3H\) and \(Hr^3\), and others don't. Six of the
    choices give two partitions that differ. The last choice, \(\langle r^3 \rangle\), gives two partitions that match
    exactly. The readout names the case. Try them all, and note which case each choice falls into. Why a subgroup
    behaves one way or the other is a question for later.</p>

  <h2>Left cosets, and where an element sits</h2>

  <div class="mc" data-answer="a">
    <p class="mc-q">Let \(H = \{e, s\}\) in \(D_6\). Which set is the left coset \(rH\)?</p>
    <button class="mc-opt" data-key="a">\(\{r, rs\}\)</button>
    <button class="mc-opt" data-key="b">\(\{r, r^5 s\}\)</button>
    <button class="mc-opt" data-key="c">\(\{r, s\}\)</button>
    <button class="mc-opt" data-key="d">\(\{e, r\}\)</button>

    <div class="mc-fb" data-key="a"><p>Right. \(rH\) is \(\{re, rs\}\): multiply \(r\) on the left of each element of \(H\).</p></div>
    <div class="mc-fb" data-key="b"><p>That's the right coset \(Hr\). Since \(sr = r^5 s\), the set \(Hr\) is \(\{r, r^5 s\}\). A left
      coset puts \(r\) on the left of each element of \(H\), not on the right.</p></div>
    <div class="mc-fb" data-key="c"><p>For \(s\) to be in \(rH\), we'd need \(s = rh\) for some \(h \in H\), so \(h = r^{-1}s = r^5 s\).
      That isn't in \(H = \{e, s\}\), so \(s\) is not in \(rH\).</p></div>
    <div class="mc-fb" data-key="d"><p>\(e\) is in \(rH\) only if \(r\) is in \(H\), since \(e = rh\) forces \(h = r^{-1}\). The element \(r\)
      isn't in \(H\).</p></div>
  </div>

  <div class="mc" data-answer="b">
    <p class="mc-q">Every element of \(D_6\) lies in how many left cosets of \(H = \{e, s\}\)?</p>
    <button class="mc-opt" data-key="a">None: \(g\) is in \(gH\) only when \(g\) is in \(H\).</button>
    <button class="mc-opt" data-key="b">Exactly one.</button>
    <button class="mc-opt" data-key="c">Two, one for each element of \(H\).</button>
    <button class="mc-opt" data-key="d">It depends on which element you pick.</button>

    <div class="mc-fb" data-key="a"><p>Every \(g\) is in \(gH\), since \(g = ge\) and \(e \in H\). The answer "none" is wrong for every element,
      not just some.</p></div>
    <div class="mc-fb" data-key="b"><p>Right. The left cosets partition \(D_6\): each element lies in exactly one of them, as the chips show.</p></div>
    <div class="mc-fb" data-key="c"><p>Two is the number of elements in each coset, which is \(|H|\). It says nothing about how many cosets
      contain a given element.</p></div>
    <div class="mc-fb" data-key="d"><p>It doesn't depend on the element. Cosets that share an element are the same coset, so the count is
      one for every \(g\).</p></div>
  </div>
</div>

  <h2>Blocks in a clock table</h2>

  <p>The reading proves that the left cosets of \(H\) partition \(G\): every element of \(G\) lies in exactly one of
    them. The clock group \(\mathbb Z_{12}\) makes that easy to see. Take \(H = \{0, 3, 6, 9\}\). Judson writes cosets
    of subgroups of \(\mathbb Z_n\) additively, as \(a + H\).</p>

  <p>Predict first: how many colored blocks will the rows fall into, and how many rows will each block hold?</p>

  <div id="d12-blocks"></div>

  <p>The rows and columns are grouped coset by coset, so the table breaks into square blocks. Each cell is shaded by
    the coset its entry lands in. Every element of \(\mathbb Z_{12}\) appears in exactly one block along the top.</p>
</div>

  <div class="mc" data-answer="b">
    <p class="mc-q">In \(\mathbb Z_{12}\), how many different cosets does \(H = \{0, 3, 6, 9\}\) have?</p>
    <button class="mc-opt" data-key="a">Two.</button>
    <button class="mc-opt" data-key="b">Three.</button>
    <button class="mc-opt" data-key="c">Four.</button>
    <button class="mc-opt" data-key="d">Six.</button>

    <div class="mc-fb" data-key="a"><p>Two cosets would need six elements each. Each coset here has the form \(a + H\), and \(H\) has four elements.</p></div>
    <div class="mc-fb" data-key="b"><p>Right: \(0 + H\), \(1 + H\), and \(2 + H\). Each has four elements, and together they make up all twelve.</p></div>
    <div class="mc-fb" data-key="c"><p>Four is the number of elements in each coset, not the number of cosets. Count the distinct sets in the table.</p></div>
    <div class="mc-fb" data-key="d"><p>Six would need cosets of two elements. The cosets here have four.</p></div>
  </div>

  <div class="mc" data-answer="b">
    <p class="mc-q">Which set is the coset \(5 + H\), for \(H = \{0, 3, 6, 9\}\)?</p>
    <button class="mc-opt" data-key="a">\(\{0, 3, 6, 9\}\)</button>
    <button class="mc-opt" data-key="b">\(\{2, 5, 8, 11\}\)</button>
    <button class="mc-opt" data-key="c">\(\{0, 5, 8, 11\}\)</button>
    <button class="mc-opt" data-key="d">\(\{1, 5, 9\}\)</button>

    <div class="mc-fb" data-key="a"><p>That's \(H\) itself, the coset of \(0\). Is \(5\) in \(H\)? No.</p></div>
    <div class="mc-fb" data-key="b"><p>Right. Add \(5\) to each element of \(H\): \(5, 8, 11, 14\), and \(14\) is \(2\) mod \(12\).</p></div>
    <div class="mc-fb" data-key="c"><p>\(0\) would need \(5 + h = 0\) for some \(h \in H\), so \(h = 7\). Seven isn't in \(H\).</p></div>
    <div class="mc-fb" data-key="d"><p>That's \(5\) added to the multiples of 4, which is the wrong subgroup. The shifts must come from \(H\), and this set has three elements, not four.</p></div>
  </div>

  <div class="mc" data-answer="c">
    <p class="mc-q">Which coset of \(H = \{0, 3, 6, 9\}\) in \(\mathbb Z_{12}\) contains \(10\)?</p>
    <button class="mc-opt" data-key="a">\(\{0, 3, 6, 10\}\)</button>
    <button class="mc-opt" data-key="b">\(\{8, 9, 10, 11\}\)</button>
    <button class="mc-opt" data-key="c">\(\{1, 4, 7, 10\}\)</button>
    <button class="mc-opt" data-key="d">\(\{2, 5, 8, 10\}\)</button>

    <div class="mc-fb" data-key="a"><p>Not a coset. The coset containing 10 is \(10 + H\). Does it contain \(0\)? That would need \(10 + h = 0\), so \(h = 2\), and 2 isn't in \(H\).</p></div>
    <div class="mc-fb" data-key="b"><p>Not a coset. Cosets aren't runs of consecutive numbers: the coset of 10 is \(10 + H\), which skips by 3.</p></div>
    <div class="mc-fb" data-key="c"><p>Right. \(10 + H = \{10 + 0, 10 + 3, 10 + 6, 10 + 9\} = \{10, 1, 4, 7\}\).</p></div>
    <div class="mc-fb" data-key="d"><p>Not a coset. Three of these, 2, 5, and 8, lie in \(2 + H\), but 10 doesn't. The coset of 10 is \(10 + H\).</p></div>
  </div>

  <div class="act-type">Proof Scaffold</div>
  <h2>Every coset is the same size as \(H\)</h2>

  <p>The chips above all had the same size, and the start of Section 6.2 proves it. Build the proof yourself. Commit to
    each step before you open it, because the argument is short and the one step that uses the group axioms is easy
    to skip. The argument uses only the group axioms and the definition of \(gH\), so it works in any group, including
    \(D_6\) above.</p>

  <div class="proof-scaffold">
    <ol class="scaffold-steps">
      <li class="sstep">
        <div class="sstep-prompt">Fix \(g \in G\). To compare the sizes of \(H\) and \(gH\), what map from \(H\) to \(gH\) would you use?</div>
        <div class="sstep-body"><p>\(\varphi(h) = gh\). If \(\varphi\) is one-to-one and onto from \(H\) to \(gH\), the two sets have the same
          number of elements.</p></div>
      </li>
      <li class="sstep">
        <div class="sstep-prompt">Why is \(\varphi\) onto \(gH\)?</div>
        <div class="sstep-body"><p>Every element of \(gH\) has the form \(gh\) with \(h \in H\), and that is exactly \(\varphi(h)\). Nothing in
          \(gH\) is missed.</p></div>
      </li>
      <li class="sstep">
        <div class="sstep-prompt">Suppose \(\varphi(h_1) = \varphi(h_2)\), so \(gh_1 = gh_2\). Which element should you multiply by, and on which side,
          to get \(h_1 = h_2\)?</div>
        <div class="sstep-body"><p>Multiply on the left by \(g^{-1}\): \(h_1 = g^{-1}(gh_1) = g^{-1}(gh_2) = h_2\). This is where the group
          axioms do the work, because \(g^{-1}\) has to exist.</p></div>
      </li>
      <li class="sstep">
        <div class="sstep-prompt">So \(\varphi\) is a bijection from \(H\) onto \(gH\). What does that say about \(|gH|\) and \(|H|\)?</div>
        <div class="sstep-body"><p>They are equal. Every left coset of \(H\) has exactly \(|H|\) elements. For \(H = \{0, 3, 6, 9\}\) in
          \(\mathbb Z_{12}\), each coset has four, as the table showed.</p></div>
      </li>
      <li class="sstep">
        <div class="sstep-prompt">Does the same idea work for a right coset \(Hg\), using \(\psi(h) = hg\)?</div>
        <div class="sstep-body"><p>Yes. If \(h_1 g = h_2 g\), multiply on the right by \(g^{-1}\) to get \(h_1 = h_2\). Every element of \(Hg\) is
          \(hg\) for some \(h \in H\). So right cosets have \(|H|\) elements too.</p></div>
      </li>
    </ol>
    <button class="btn411 ghost scaffold-all" type="button">Reveal the whole proof</button>
  </div>

<div class="act flaw">
  <div class="act-type">Spot the Flaw</div>
  <h2>Left and right always agree?</h2>

  <p>A classmate skips the two-column widget with a quick argument that left and right cosets always agree. The
    misconception underneath is that a group element can be slid past an element of a subgroup. Here is the argument.</p>

  <p><strong>Click the step that isn't justified.</strong></p>

  <div class="flaw-widget" data-flaw="2">
    <div class="flawlist">
      <button class="fline" type="button">Take any \(x \in gH\). Then \(x = gh\) for some \(h \in H\).</button>
      <button class="fline" type="button">Elements of a subgroup commute with everything in the group, so \(gh = hg\).</button>
      <button class="fline" type="button">Therefore \(x = hg \in Hg\), which shows \(gH \subseteq Hg\).</button>
      <button class="fline" type="button">Running the same argument with the roles reversed gives \(Hg \subseteq gH\), so \(gH = Hg\).</button>
      <button class="fline" type="button">Since \(g\) and \(H\) were arbitrary, \(gH = Hg\) for every subgroup \(H\) and every \(g\). \(\blacksquare\)</button>
    </div>

    <div class="flaw-verdict" data-key="1"><p><strong>Fine.</strong> That's the definition of \(gH\).</p></div>
    <div class="flaw-verdict" data-key="2"><p><strong>This is the flaw.</strong> Being in \(H\) doesn't make \(h\) commute with \(g\). In \(D_6\), take
      \(H = \{e, s\}\), \(g = r\), and \(h = s\). Then \(gh = rs\), but \(hg = sr = r^5 s\), which is a different element.</p></div>
    <div class="flaw-verdict" data-key="3"><p><strong>Fine.</strong> It follows from line 2, and the inclusion
      itself is valid. The error sits upstream, in line 2.</p></div>
    <div class="flaw-verdict" data-key="4"><p><strong>Fine as reasoning.</strong> It runs line 2 backward, so it
      stands or falls with line 2. It adds no new error of its own.</p></div>
    <div class="flaw-verdict" data-key="5"><p><strong>Fine as a generalization.</strong> Whatever the argument
      proves for arbitrary \(g\) and \(H\) holds for all of them. What it proves is false only because of line 2.</p></div>
  </div>
</div>
